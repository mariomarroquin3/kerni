# Audit after the team changes, and the exit order fix

## Request
"There are changes in Kerni, I think there is a disaster: audit." Then: review what was there before, and review the riskiest new code.

## Findings
- **Nothing was lost.** Since the last verified commit (`2850250`, 117 commits by two accounts) only `Convertir a Markdown/` was deleted (John's own Python script, removed in his cleanup commit; `npm run pdf-a-md` covers it). The 13 fixes and features checked by name are all still in the code. Suites: backend 275 -> 556, front 97 -> 223, Rust 32 -> 87, all green.
- **Secrets.** No `.env` has ever been committed in any branch (only `.env.example`, with no values); GitHub answers 404 for `src/backend/.env`, `.env` and `supabase/local/.env`; no Supabase, Gemini, Anthropic or OpenRouter key appears in the history. Authorship is clean: two accounts, no co-author or "generated by".
- **Real runtime problem, outside the code.** The local `.env` has `LLM_PROVIDER=anthropic` with an empty `ANTHROPIC_API_KEY`, so the backend starts without a model ("local automatic answers"). The Gemini and OpenRouter keys are set. Left as is on request.
- **Risk review.** The MCP client (fixed endpoint, no redirects, size and time caps, sanitized output, off by default), the browser cache cleaner (only `Cache` and `Code Cache`, no input paths), the opt-in clipboard monitor (off by default, nothing leaves the PC until the person taps Review) and process freezing (same checks as closing) are well scoped.

## Decision
- **`salir()` armed the forced exit after resuming the frozen processes.** If resuming one hung, the 3 second failsafe never started and "Cerrar Kerni" could hang again. The forced exit thread is now started first, then the frozen processes are resumed, then the normal exit. A test checks the order in `lib.rs`.
- Not changed (reported only): `LOCALAPPDATA` unset in the cache cleaner, four env vars missing from `.env.example` (`CORS_ORIGINS`, `GEMINI_MAX_TOKENS`, `MAX_TOKENS_RESPUESTA`, `SUPABASE_SERVICE_ROLE_KEY`), `contents: write` at workflow level in `release.yml`, six open dependabot branches.

## Verification
- Front 224 tests (1 new), Rust 87, backend 556 (unchanged in this step).
- Not verified: the exit order in the real compiled window.
