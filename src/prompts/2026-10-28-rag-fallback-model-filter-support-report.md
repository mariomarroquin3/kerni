# RAG fallback, manuals by model, support report and reboot notice

## Request
"Let's implement what you propose": the four proposals ranked first in the bug review.

## Decisions
- **1. Fallback when the model cannot answer** (`rag/respaldo.js`, `routes/chat.js`). The free Gemini plan allows about 20 requests per day, which is the biggest risk for daily use and for the presentation. When the model fails with `sin_cupo` (or a generic service failure), Kerni answers with the two closest passages of its guides, with source and page, and says plainly that it is guide text copied as is, not a model answer. If the request is a clear one (`intenciones.js`), the confirmation card is added too, so "which programs open at startup" works with no model at all. It does not cover invalid key or no network: the person needs to know about those. Without relevant guides the usual error stays. The failed turn is not kept in the session.
- **2. Manuals by model** (`rag/modelo.js`). Manuals of a model live in `privado/<brand>-<model>/`, so the folder says which model each passage belongs to; no migration and no reindexing. When the equipment is known a manual of another model is dropped (this PC is an Inspiron 14 7435, so the Latitude 3120 manual would have given wrong answers about soldered RAM) and the right one gets a small boost; general guides always stay. If the question names the model, that manual is valid whatever the equipment. More candidates are requested when the equipment is known so the filter does not leave the list short. Checked against the real cloud knowledge base: the Latitude manual appears with "Latitude 3120", disappears with the Inspiron, and comes back when the question names the Latitude.
- **3. Support report** (`ver_reporte_soporte`). A plain text summary for the institution's technician: equipment, system, processor, memory, disk, battery, time since the last full boot, the 5 heaviest processes, active startup programs and network. Built in the interface from what the app already knows; no new Rust command. It never includes paths, commands or the user name, it is only shown, and it is copied only if the person presses the button. Updates are left out because they take minutes. Menu entry, chat intent (backend and front) and tests included.
- **7. Reboot notice.** `Metricas.encendidaS` from `sysinfo::System::uptime`. From 7 days, once per session and at most once a day, Kerni says how long it has been and that Shut down is not enough with Windows fast startup: choose Restart. It only advises.
- **Bug found on the way:** `sanearParaBloque(texto, max)` ignored its second argument, so the caps that `contexto()` passed (80 and 1200 characters) were never applied. It now cuts when a limit is given.
- **Two flaws of the small model seen in real runs.** It said "let me look that up" without calling `buscar_conocimiento` (the persona now says to call it BEFORE answering, never promise it), and once it ended blank right after reading the tool result, which showed "me enredé". The agent now retries once when the final answer is empty after a tool, without keeping the empty message in the history; it does not retry without a previous tool or twice.
- Not done yet from the list: battery health, security status and print queue reset (4, 5, 6, 8).

## Verification
- Backend 275 tests (22 new: model detection and filtering, the search asking for more candidates, fallback text without diminutives or emojis, the chat fallback in every case including the ones where it must not apply, the report intent). Front 93 (8 new: report content and privacy, panel, reboot notice, wiring). Rust 32 (+3 real-system, ignored).
- Real: search against Supabase Cloud with four equipment cases (above). Browser demo: report panel with the copy button and the reboot notice with `?dias=12`.
- Not verified: a real 429 from Gemini (the fallback is covered with a failing provider in tests), the clipboard in the compiled Tauri window, and the Linux build.
