# Guided mode: four fixed step guides

## Request

Add a guided, step-by-step mode to Kerni. Four fixed guides (PC lenta, impresora fuera de línea, espacio en disco, actualizaciones pendientes), state saved in SQLite per device, one step per turn, and the model used only for open questions inside a step. Kerni proposes, the person decides: any action step is a proposal that goes through the existing card. Local commits only, no push.

## Decisions

- **Guides are data.** The steps live in `src/backend/src/guias/guias.js`. Each step is `instruccion` or `accion`; an `accion` carries a name from `ACCIONES` (and a destination from `DESTINOS_AJUSTE` for `abrir_ajuste`). Texts were written against the guides in `conocimiento/windows/` (printers, performance, disk space, updates); no Office guide was needed because none of the four covers Office. The Windows 11 paths were copied from those files, not from memory.
- **Action steps only propose.** The engine runs each action step through `validarPropuesta` with no system snapshot (these actions carry no pid). A proposal that fails validation is dropped and logged; the step is still shown. A test checks that the engine only touches the guide store and never executes anything.
- **Closed answers.** `listo`, `no_pude`, `salir` are the only inputs. `no_pude` keeps the step and offers one help line. Unknown ids and out-of-range saved steps are rejected or cleared.
- **Memory off means refused.** A session-only mode was judged confusing (the position would vanish on restart), so a guide request without memory (or without a device id) gets a clear message and no model call. "Olvidar todo" clears the guide row.
- **Model context.** While a guide is open, the model receives the current step inside `<guia>` as data. The reply is always closed with the current step line (`cerrarConPaso`), whatever the model wrote, so the step index only ever comes from the database.
- **Chat without the model.** `listo`, `no pude` and `salir` are answered locally while a guide is open. A guide starts only with an explicit request ("guíame", "paso a paso") plus a topic; a plain "mi pc va lenta" still goes to the slow-PC diagnosis. A negation or a long message does not start a guide.
- **Front.** One line above the chat, pure logic in `web/guias.js`, text via `textContent`. While a guide is open, or when the person asks for one, the front does not run its local rules first, so they cannot cut a step short.
- **Existing test changed.** `test/integracion.test.js` looked for the exact line `if (responderAutomatico(mensaje)) return;`. The line now has the guide guard in front of it, so the anchor was shortened and a regex for the new guard was added. The local-first order it checks is unchanged.
- **Pre-existing working-copy state.** `src/backend/src/routes/chat.js`, `src/desktop/web/estado-ia.js` and `src/desktop/test/estado-ia.test.js` showed as modified before the session. `git diff --ignore-cr-at-eol` on them was empty: the difference was line endings only. `chat.js` was edited, and its commit contains only the guide hunks (63 changed lines, checked with `git diff`). The two estado-ia files were not touched and are not committed.
- **Commit plan.** Six commits, each one topic: guide data, persistence, engine and routes, chat and panel integration, docs, this log.
